# Project patterns

- **Medium confidence:** For badges on stretched-link lists, inspect the visible-name hierarchy and hit testing. Place beside the name outside clipping, keep interactive markup outside anchors, and restore pointer events in the same shadow stylesheet as WXT's reset.

- **Medium confidence:** A working Nansen card alongside a venue's missing target points to discovery, not coverage. Dexscreener has provider-specific chain slugs and both address-sized and bytes32 pool identifiers; validate resolved base-token identity before fetching evidence.
- **Low confidence:** Verify financial SVGs at their actual container size; label price/value units and preserve precision for tiny-price instruments. Do not let generic two-column tab layout strand a wide table below a chart.

- **High confidence (repeated user reports + live validation):** Separate asset discovery from market identity. Show broad spot/perp catalogs for X/DEX exploration, but bind each verdict to exact chain+contract or perp coin. Never cross-chain substitute a venue ticker.

- **High confidence (live verified):** Native ETH is trackable through Nansen's 0xeeee identifier on its selected ETH chain. Translate zero/NATIVE venue markers; do not classify ETH as unsupported simply because it has no ERC-20 contract.

- **High confidence (3 confirmations):** Host clipping affects tooltip labels independently of badge/card placement; verify each surface separately and use native top-layer rendering for floating labels.

- **Medium confidence (user-confirmed):** Jumper zero-address values can mean selected native ETH. Preserve the selection, identify the chain-native symbol, and never call token-contract APIs with the sentinel.

- **Medium confidence (2 confirmations):** Missing badges on every author can be a stopped local backend. Verify health first and keep user-facing local servers detached from the tool turn; offline author results must recover when service returns.

- **Low confidence (1 confirmation):** Suppress venue guard UI during asset selection and before a destination exists; revalidate on close, and never substitute a token from another chain solely by ticker.

- **Medium confidence (2 confirmations):** Use actual token identity plus versioned caches for logo data; replay token fixtures cannot safely answer arbitrary logo requests.
- **Medium confidence (2 confirmations):** Real host-page overlays require native top-layer promotion where available; internal z-index fixes alone do not cover clipping/transform boundaries.
- **Low confidence (1 confirmation):** Distinguish token mints from Dexscreener pool IDs and resolve the exact base token server-side before requesting Nansen evidence.

- **Low confidence (1 confirmation):** Replay entity fixtures do not prove real account coverage; label replay UI and verify real identities through the live backend.
- **Low confidence (1 confirmation):** For X profile badges, support both scoped legacy test IDs and the live semantic heading/adjacent handle shape; always match the displayed handle to the route before mounting.

- **Low confidence (1 confirmation):** Restore host-page layout through WXT's onRemove lifecycle; wrapping the public remove method misses context invalidation, which calls WXT's internal removal closure.

- **Low confidence (1 confirmation):** In E2E accessibility coverage, query by role and computed accessible name instead of coupling tests to `aria-label`; use attribute assertions only when the attribute itself is required.
- **Low confidence (1 confirmation):** Any floating hint inside a clipped surface needs a placement that points into the surface, plus a reduced-motion override.
- **Low confidence (1 confirmation):** Wrap persistent test-fixture mutations in `try/finally` immediately; await and validate cleanup, then close pages/contexts in a nested `finally`.
- **Low confidence (1 confirmation):** Shadow-tree `!important` rules outrank outer inline `!important`; repair a reset conflict with a later same-shadow `:host` rule and prove stacking from computed styles in Chromium.
