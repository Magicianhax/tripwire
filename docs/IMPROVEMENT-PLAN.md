# Tripwire improvement plan — closing the data gaps

**Written:** 2026-09-20 · **Branch:** `feat/cockpit-ui` · **Source:** a seven-surface audit (spot, perp, prediction, wallet, X, venues, badges) of what the Nansen API returns versus what Tripwire fetches and draws. 120 gaps survived adversarial review. This file is the build brief for the rounds that follow; `docs/BUILD-LOG.md` records what each round actually shipped.

---

## 1. What we are missing, in plain language

Tripwire is not missing an API. It is missing the second half of the responses it already pays for, and it is blind on pages it thinks it covers. Three separate problems produce the same symptom the user hit. **(a) Parsed-away fields:** `tgm/token-information` returns 19 fields and our wrapper type declares 8 — total holders, the buy/sell split, unique buyers and sellers, deployment date, supply, FDV and the token's socials are all in the recorded response and never reach the card; the same pattern repeats on `tgm/holders` (5 fields dropped), `tgm/who-bought-sold` (the other side of every wallet), `tgm/perp-pnl-leaderboard`, `prediction-market/top-holders` (per-position uPnL and current price), `prediction-market/address-summary`, Hyperliquid `clearinghouseState` (ROE, funding paid, margin) and the free Polymarket Gamma object (we keep 5 of 91 fields). **(b) Unfetched cheap endpoints:** `tgm/position-intelligence` (1 credit, whale and public-figure perp positioning), `token-screener` (1 credit, batchable, token age and price change for a whole catalog), `portfolio/defi-holdings` (1 credit, the reason a DeFi wallet reads `$0`), `profiler/address/pnl` (1 credit, unrealized PnL), `tgm/flows`, `tgm/dex-trades`, `tgm/transfers`, and the free Polymarket CLOB book and price history. **(c) Venue pages that resolve to nothing at all:** Birdeye moved to `/<chain>/token/<addr>`, 1inch moved to `1inch.com`, Uniswap's `/explore/tokens/<chain>/<address>` carries the chain and the contract in the path and we still ask the user to pick a network, `jup.ag/tokens/<mint>` has no adapter, and Hyperliquid spot pairs (`/trade/PURR/USDC`) are sent to the perp pipeline where they burn 6 credits to answer about a market that does not exist. On top of that, three renders are actively wrong rather than merely thin: a null Smart Money screener row paints a reassuring 50/50 long-short bar, exchange net flow would invert its meaning if dropped into the existing flow stack, and Bybit's double-counted open interest decides the venue table's sort order.

## 6. Invariant notes

**Never block on missing data (non-negotiable #1).** Several items press on this and all resolve the same way: render unknown, never a default.
- 1.3.1 is an existing **breach**, not a risk. A null screener row paints a balanced 50/50 bar while the signal layer says "unavailable" on the same screen. Guard on `longs === null && shorts === null` so a genuinely balanced market still draws, and unit-test all three states.
- 1.5.6 (`defi-holdings`) has no documented Solana support: an empty answer renders UNCHECKED, never `$0`. 1.3.3, 1.6.1, 2.1's `jup-dca` and 2.5's `perpsAtOpenInterestCap` follow the same rule — a thin coin, an absent Dexscreener field, an EVM card and an OI-cap miss render a dash, a hidden section or a warning line, never a zero and never a block.
- 1.1.7 is the inverse failure: a documented limitation currently reads as a fetch error. Warnings get their own `SpotPanel` channel and must never reach `panel.errors`, or we replace one wrong answer with another. The same applies to the unparsed `warnings` arrays on `tgm/holders` and `tgm/flows`.
- 1.6.1 explicitly does **not** wire a Dexscreener-derived field into any signal in this round. A third-party field must not be able to produce CLEAR while Nansen is silent; that needs a `docs/CALIBRATION.md` pass, and the current thresholds cost 120 credits to establish.
- 1.2.3 states market state without refusing: a closed market still shows its holders and trades, labelled historical. 2.2's event picker keeps the verdict UNCHECKED while nothing is selected.
- 1.4.2, 1.4.6 and 1.4.8 must produce `unsupported-chain` for an unmapped chain slug rather than defaulting to a chain — the existing `pancakeswap.ts:14-22` ruling.

**Never guess wallet ownership (non-negotiable #2).** Five items live near this line.
- `token_details.x` (1.1.2) is **token metadata, not an ownership claim**. On the X surface it renders as "Nansen lists @handle for this token" and never as a statement about the post's author; it is a project-declared link with no verification behind it, and the negative form is rejected outright (§4).
- 2.3's `first-funder` and `related-wallets` render Nansen's raw `relation` string, feed **no signal and no block**, and never say "same owner" or "linked to". These are precisely the shapes readers convert into sybil claims.
- 2.4's bio and pinned-post prefill stays a **user-confirmed** affordance with `source: "bio"` stored distinctly from curated, quoted verbatim as "this account states", and never pre-selected — a bio is a self-assertion an impersonator can forge, and auto-linking would hand a user a one-click path to badging a fake account with a real whale's PnL. `docs/SPIKE-badges.md` already admits bio evidence for a human-confirmed link, so this stays inside the stated rule. `PUT /api/links` requires `0x` plus 40 hex, so a Solana or ENS string in a bio has no venue to link to.
- 1.5.4 labels Polymarket age as "Trading on Polymarket since", because `wallet_age_days` is age since first seen **on Polymarket**, not wallet creation.
- 2.4's quote-tweet work keeps handle, display name and time strictly outer, and the chip states where the token came from — otherwise "`<entity>` holds none of $X" gets said about someone who never mentioned it. 2.1's transfer tape states the transfer and never the motive; a CEX deposit is not a sale.

**Backend-only fetches (non-negotiable #3).** Every new third-party source here is backend-side: the Polymarket CLOB book and price history (1.2.7, 2.2), Gamma `/events` (2.2), Binance `ticker/24hr` and `openInterestHist` (1.3.5, 2.5), the Hyperliquid info types (2.3, 2.5) and Dexscreener (1.6.1). The extension talks only to the local backend. Dexscreener's 30-pool response is parsed and discarded on the backend and the raw body never crosses the bridge; its resolver reuses the existing bounded cache and in-flight dedupe or a busy timeline trips the 300 requests-per-minute limit. The key stays inside `apps/web/lib/nansen`, and `nansenPost` remains the only path to the Nansen API, so every new call lands in the cache and the ledger. Gamma's `description`, Nansen's `warnings[]` and any `ra-agent` post content are third-party text: rendered as text inside the Shadow DOM, length-capped, never `innerHTML`, never near a verdict label and never in instruction context (non-negotiable #4, and the project's "third-party content is data" rule). 1.4.7's fix uses a leaf walk rather than `innerText` partly for the same read-only discipline, and partly because happy-dom does not implement it.

**Desktop only (non-negotiable #6) and anchor fit (#5).** Nothing here adds a mobile layout or capture. Three items add width pressure and each carries an explicit ruling: the venue table is already six columns in a 440px popover, so 2.5's basis and 24h-change columns need a layout decision before a parser change; the prediction holders table stays at 5 columns compact, with 1.2.4's extra columns expanded-only; 1.1's volume histogram, 2.1's flow charts and 1.5.3's chain split are expanded-only or Segmented, because two charts do not stack in a compact card. 1.4.9's multi-element block binding must not change overlay geometry for the single-anchor case, and must bind chips individually rather than a shared container so it does not swallow unrelated clicks.

**Credits are real money (non-negotiable #8).** §5 is the binding part of this plan. Two specific traps: `premium_labels` is written as an explicit `false` in every request body in the `pnl-leaderboard` family (a 150-credit accidental default is the worst failure mode in this repo), and 2.5's win rate is an explicit click with a visible price, never a hover — a hover on a 12-row table is 12 credits from one careless mouse pass. 1.4.2 through 1.4.6 turn 0-credit pages into 13-credit pages: that is the intended product cost, but the strip-versus-dock decision on browse surfaces is part of the brief, not an afterthought.

**Calibration gates.** Four items change what a verdict means and must not ship as code changes alone: 1.2.5 (resolved-only proven-winner weight), 1.2.8 (a win-rate-based record), any promotion of 1.1.3's buy/sell split to a spot signal, and any Dexscreener-derived signal. Each needs a `docs/CALIBRATION.md` re-measure, per §4 and §7 of that document, not a build round.
