# Tripwire Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Tripwire: a Chrome extension with a local Next.js backend that shows Nansen-backed verdicts on X posts and blocks or warns on trade buttons across spot, perp and prediction venues.

**Architecture:**
- **Monorepo** (pnpm):
  - `packages/core`: pure signals, rules and schemas.
  - `apps/web`: Next.js API with the Nansen client, cache, ledger and pages.
  - `apps/extension`: WXT MV3 extension with content scripts, adapters and Shadow DOM UI.
- **Data path:** the extension talks only to the backend, and the backend talks only to Nansen.

**Tech Stack:**
- TypeScript, pnpm workspaces
- Next.js (App Router), React
- WXT (MV3)
- zod, Vitest, Playwright
- `node:sqlite` (built-in, no native build step on Windows)

**Spec:** `docs/superpowers/specs/2026-09-17-tripwire-design.md`

## Global Constraints

- Node >= 22.13 (for `node:sqlite`); pnpm >= 9.
- Nansen base URL `https://api.nansen.ai/api/v1`, header `apikey`. The key comes only from `apps/web/.env.local` → `NANSEN_API_KEY`.
- The key never appears in extension code, logs, fixtures or commits.
- The backend binds to `127.0.0.1:3000`.
- Missing data → signal `value: null` → never counts toward CLEAR (verdict UNCHECKED).
- Visual direction **A: Hazard**:
  - safety yellow `#FFD400` on ink `#0B0B0B`, used only for CAUTION/TRIPWIRE
  - Archivo (condensed) for display, JetBrains Mono for numbers, Schibsted Grotesk for body text
  - no gradients, glassmorphism or numbered section markers
- No wallet access, signing or transaction interception.
- `TRIPWIRE_REPLAY=1` serves fixtures and shows a REPLAY watermark.

### Task 3: Spot, perp and prediction signals (TDD)

**Produces:**
```ts
spotSignals(input:{flow?:FlowRow|null; netflow?:NetflowRow|null; indicators?:IndicatorsResp|null; author?:{entity:string;valueUsd:number}|null}): Signal[]
perpSignals(input:{side?:"long"|"short"; screener?:PerpScreenerRow|null; positions?:PerpPosition[]|null; markPrice?:number|null}): Signal[]
predictionSignals(input:{outcome?:"yes"|"no"; holders?:Holder[]|null; pnl?:Record<string,number>|null}): Signal[]
```

**Signal definitions:**
- **`exit_pressure`:** value = labeled net flow (smart_trader + whale + public_figure) in USD. Fires as warn when negative while fresh-wallet net flow is positive. Null when flow is missing.
- **`fresh_buy_share`:** value = percentage (0–100) of positive inflow coming from fresh wallets, i.e. fresh_pos / (sum of positive segment flows). Null if there's no positive inflow.
- **`sm_netflow_24h`:** value = `net_flow_24h_usd`. Null when missing.
- **`risk_high_count`:** value = count of risk indicators scored `high`. Null when missing.
- **`author_holds_token`:** value = author entity's USD value in the token, severity info.
- **`sm_opposite_side_pct`:**
  - longs L, shorts |S|.
  - side long → value = |S| / (L + |S|) × 100; side short → L / (L + |S|) × 100.
  - Null when there's no side or total is 0.
- **`inside_liq_band`:** value = USD of Smart Money positions whose liquidation_price is within ±3% of mark. Null when there are no positions or no mark price.
- **`smart_side_disagrees`:**
  - Weight per holder = max(0, pnl) + 1000 floor (weight 0 if pnl < 0).
  - value = weighted share (%) of position on the opposite outcome from the chosen one.
  - Null when there's no outcome or no holders.

Each signal includes an evidence list citing the endpoint name, the field and the formatted value.

- [ ] **Tests** (each case asserts value and nullability):
  - flows with fresh_wallets null → `fresh_buy_share` null
  - all segments negative → `exit_pressure` negative value
  - no side → `sm_opposite_side_pct` null
  - long with L=4.2M, S=−1.8M → 30
  - liquidation band at 2.9% vs 3.1%
  - holders all on NO with positive pnl and outcome yes → 100
- [ ] Implement, get tests passing, commit.

### Task 4: Rules engine and presets (TDD)

**Produces:**
```ts
type Rule = {id:string;kind:"spot"|"perp"|"prediction";signal:SignalId;op:">"|"<"|">="|"<=";threshold:number;action:"warn"|"block";enabled:boolean;text:string};
type RuleHit = {rule:Rule;signal:Signal};
type Verdict = "CLEAR"|"CAUTION"|"TRIPWIRE"|"UNCHECKED";
evaluate(rules:Rule[], signals:Signal[], kind:Target["kind"]): {verdict:Verdict; hits:RuleHit[]; unavailable:SignalId[]}
PRESETS: Record<"degen"|"balanced"|"paranoid", Rule[]>
```

**Verdict logic:**
- Only enabled rules of the matching kind are evaluated.
- A rule whose signal is null is added to `unavailable`.
- Any block hit → TRIPWIRE, else any warn hit → CAUTION, else any unavailable → UNCHECKED, else CLEAR.

**Balanced preset:**
- spot:
  - `exit_pressure < -100000` → block
  - `fresh_buy_share > 70` → warn
  - `sm_netflow_24h < -50000` → warn
  - `risk_high_count >= 2` → block
- perp:
  - `sm_opposite_side_pct > 70` → block
  - `inside_liq_band > 1000000` → warn
- prediction:
  - `smart_side_disagrees > 70` → block

**Other presets:** Degen doubles the magnitudes and only blocks at the extremes. Paranoid halves the magnitudes and turns the warns into blocks.

- [ ] **Tests:**
  - an empty signal set → UNCHECKED
  - block beats warn
  - disabled rules are ignored
  - rules of another kind are ignored
  - CLEAR only when all rule signals are non-null and no rule fires
- [ ] Implement, get tests passing, commit.

### Task 5: Backend foundation (Next.js, db, Nansen client) (TDD for client)

**Produces:**
```ts
// lib/nansen/client.ts
nansenPost<T>(opts:{name:string; path:string; body:unknown; ttlMs:number}): Promise<{data:T; cached:boolean; creditsUsed:number|null}>
class BudgetExceeded extends Error {}
class NansenError extends Error { status:number }
// lib/db.ts
getDb(): DatabaseSync  // tables: cache(key PK, value, expires_at), ledger(id, ts, endpoint, status, credits, latency_ms, cached), rules(id PK=1, json), overrides(id, ts, target_json, verdict, hits_json)
```

**Client behaviour:**
- **Key and cache:** key = `path + stable JSON of body`. Memory Map (max 500) → sqlite cache → network.
- **Deduplication:** an in-flight Map shares one promise.
- **Budget:** summed `X-Nansen-Credits-Used` for today ≥ `NANSEN_DAILY_CREDIT_CAP` → serve stale cache if present (marked `stale:true`), else throw BudgetExceeded.
- **Rate limit:** a token bucket of 10 requests per second.
- **429:** wait `Retry-After` seconds (default 1), retry once.
- **Ledger:** each network call writes one ledger row; cache hits don't.
- **Replay:** `TRIPWIRE_REPLAY=1` reads `fixtures/nansen/<name>.json`, with no network.

- [ ] Scaffold Next.js in `apps/web` (App Router, TS, no Tailwind; custom CSS with Hazard tokens). `dev` script: `next dev -H 127.0.0.1 -p 3000`.
- [ ] **Vitest tests** with `fetch` mocked and the db pointed at a temp file (`TRIPWIRE_DB`):
  - a second call is served from cache with no fetch
  - two concurrent calls → one fetch
  - 429 then 200 → two fetches
  - a cap of 5 with credits used 5 → BudgetExceeded
  - replay reads the fixture
- [ ] Implement, get tests passing, commit.

### Task 7: API routes and CORS

**Validation and errors:**

**CORS:**
- Allow `chrome-extension://*` origins, plus same-origin for pages, via the `TRIPWIRE_EXTENSION_ORIGIN` env var (optional exact pin).
- Requests with no Origin (curl, or the extension background, which sends its own origin) are allowed only from loopback, which the host binding already ensures.

### Task 12: Venue adapters and guard runner

**Adapter interface** (from the spec): `{id, tier, match(url), readTarget(doc,url), anchor(doc)}`.

**Tier 1 adapters:**
- **Jupiter:**
  - `jup.ag/swap/<in>-<out>` or `?sell=&buy=` → spot solana (out mint).
  - Anchor: a button whose text matches `/^(swap|place order)$/i`.
- **pump.fun:** `/coin/<mint>` → spot solana. Anchor: the button matching `/place trade|buy/i`.
- **Uniswap:**
  - `?outputCurrency=0x…&chain=base|ethereum|arbitrum…` → spot evm.
  - Anchor: the button matching `/^swap$/i` or `[data-testid="review-swap"]`.
- **Jumper:** `?toToken=0x…&toChain=<id>` → chainId map `{1:ethereum, 8453:base, 42161:arbitrum, 56:bnb, 137:polygon, 10:optimism, 43114:avalanche, 1151111081099710:solana}` → spot. Anchor: the button matching `/exchange|swap|bridge|review/i`.
- **Hyperliquid:**
  - `app.hyperliquid.xyz/trade/<COIN>` → perp. Side comes from the active Long/Buy vs Short/Sell toggle (`aria-pressed`/active class, heuristic by text).
  - Anchor: the button matching `/^(buy|sell|long|short)/i` in the order form.
- **Polymarket:**
  - `polymarket.com/event/<eventSlug>[/<marketSlug>]` → prediction slug (the market slug if present, else the event slug).
  - Outcome from the selected Yes/No button text.
  - Anchor: the button matching `/^(buy|trade)/i`.

**Tier 2 adapters** (URL-only spot, dock only):
- raydium `?outputMint=`
- aerodrome `?to=`
- pancakeswap `?outputCurrency=`
- 1inch `/#/<chainId>/…/<from>/<to>`
- matcha `?buyAddress=`
- cow `/#/<chainId>/swap/<sell>/<buy>`
- axiom, photon, gmgn, bullx: path contains a base58 or 0x address
- dexscreener `/<chain>/<pair>` (the pair address is used as the token only if the token lookup resolves; otherwise UNCHECKED)
- birdeye `/token/<addr>?chain=`

**Runner** (`venues.content`):
- Watches URL changes (a history API patch plus a 1s poll) and DOM changes (debounced 400ms).
- On a target change: `guard` →
  - tier 1: TRIPWIRE → BlockScreen overlay absolutely positioned over the anchor's rect (ResizeObserver keeps it in sync); CAUTION, UNCHECKED or CLEAR → Strip above the anchor.
  - tier 2, or anchor missing: Dock.
- Override: POST `/api/override` → unlock for 60s.

- [ ] **Tests:** each adapter's `match` and `readTarget` against URL cases, and `anchor` against small HTML fixtures. Commit.
